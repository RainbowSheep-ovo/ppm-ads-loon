# 「故障」弹窗分析：它是什么，能不能去掉

> 结论先说：**它不是服务器下发的推广位，是写死在 App 里的「反广告拦截」提示，Loon 无法移除。**
> 本文给出判断依据、以及三条实际可选的路线。

---

## 1. 弹窗原文

第三次抓包后，开启插件冷启动时出现：

```
故障
无法正常联网，导致广告无法显示！
请升级最新版应用，联网并关闭相关广告屏蔽软件，然后重启应用！
前往设置-更新地址，可下载最新版，如想去广告可以捐赠喵喵特权！
更多资讯关注微信公众号 tips21

                                          确定 (9s)
```

同时开屏容器右上角有「剩余 4 喵」、右下角有「下载」。

---

## 2. 为什么判断它是 App 内置的，而不是"服务器下发的推广位"

三条依据：

### 2.1 第三次抓包里没有任何"要弹窗"的网络请求

56 条请求逐条看下来，全部业务域名如下：

| 域名 | 用途 |
| --- | --- |
| `dev.azure.com` / `gitcode.net` / `jihulab.com` / `gitlab.com` / `github.com` | 拉配置文件 `users_ios_free`、`app_ios_store_free`、`version_ios` |
| `api-access.pangolin-sdk-toutiao-b.com` | 穿山甲拉广告（返回 40006） |
| `mssdk.volces.com` / `toblog.ctobsnssdk.com` / `tnc3-alisc1.zijieapi.com` | 字节埋点 / TTNet |
| `uop.umeng.com` / `alogs.umeng.com` | 友盟推送 / 统计 |
| `ip-api.com` | 归属地（返回香港） |
| `mmbiz.qpic.cn` | 公众号配图 |

**没有任何一条请求的返回内容能对应到这个弹窗**。没有"公告接口"、没有"弹窗配置接口"。

### 2.2 触发条件与「有没有广告」完全对应

| 抓包 | 开屏广告情况 | 是否弹窗 |
| --- | --- | --- |
| 第二次（未装插件） | AdMob 成功填充，播放视频插屏 | **没弹** |
| 第三次（装了插件） | AdMob 被拦 + 穿山甲返回 40006 | **弹了** |

第三次里，穿山甲 `get_ads` 返回的是**开发商自己服务器**的错误：

```json
{"request_id":"8734A64A-F03A-4EF5-9190-C1B23B763B0E",
 "status_code":40006,"reason":0,"desc":"广告位ID不合法"}
```

也就是说：**即使不装任何插件，只要开屏最终没有广告可放（包括开发商自己配错广告位），这个弹窗也会弹。**

这条最关键——它证明弹窗的判定标准是「开屏没广告」，而不是「检测到你用了广告屏蔽软件」。所以它是**结果导向的惩罚**，不是特征检测。

### 2.3 措辞是典型的反 adblock 话术

> "联网并**关闭相关广告屏蔽软件**，然后重启应用！"
> "如想去广告可以**捐赠喵喵特权**！"

前半句是威胁，后半句是引导付费。这是标准的「广告拦截对抗（anti-adblock）」设计，不是业务公告。

---

## 3. 为什么 Loon 去不掉

Loon 的能力边界是**改网络流量**（DNS、路由、TLS 解密后的 HTTP 请求/响应）。它改不了：

- App 本地的 `UIAlertController`（原生弹窗）
- 弹窗上的 9 秒倒计时（`Timer`，纯本地）
- 开屏容器右上角的「剩余 4 喵」（本地 UI 元素）

这个弹窗的触发点是广告 SDK 的回调函数（`didFailToReceiveAd`），中间**没有网络请求参与**。既然没有请求，就没有可以伪装的响应。

同理，如果让广告 SDK 收到「成功」回调，它就必须真的拿到一条广告——那广告就会显示出来。两者互斥。

---

## 4. 三条实际可选的路线

| 方案 | 开屏广告 | 「故障」弹窗 | 实际体验 |
| --- | --- | --- | --- |
| **A. 维持拦截**（当前插件） | 无 | 有，9 秒 | 省 5 秒广告，多付 9 秒弹窗 |
| **B. 关闭插件** | 5 秒视频 | 无 | App 的原始设计，其实更省时间 |
| **C. 官方"喵喵特权"** | 无 | 无 | 弹窗里给的正路：捐赠后成为特权用户 |

**说实话：对这个 App 而言，A 的净收益是负的。** 5 秒广告 vs 9 秒弹窗，拦截反而更亏。

这不是插件写错了，是开发商专门设计成这样的——正因为有人做去广告插件，他们才加了这层惩罚。

## 5. 唯一值得一试的实验（成功率不高）

有一个未经验证的猜想：如果弹窗是按**「网络错误」**触发的（文案确实写的是"无法正常联网"），那么把「连接失败」换成「请求成功但返回空」，可能让 App 走"无广告、静默跳过"的分支，而不是弹窗。

具体做法是**不 REJECT 域名，而是让请求返回空的 HTTP 200**（需要开启 MITM）：

```
[URL Rewrite]
^https?:\/\/googleads\.g\.doubleclick(-cn)?\.net\/mads\/gma reject-200
^https?:\/\/pagead2\.googlesyndication(-cn)?\.com\/ reject-200
^https?:\/\/pagead2\.googleadservices(-cn)?\.com\/ reject-200

[MITM]
hostname = googleads.g.doubleclick-cn.net,googleads.g.doubleclick.net,pagead2.googlesyndication-cn.com,pagead2.googlesyndication.com,pagead2.googleadservices-cn.com,pagead2.googleadservices.com
```

**注意**：Loon 的 Rewrite 在规则匹配**之前**执行，所以这个方案要把插件里 AdMob 那几条 `DOMAIN-SUFFIX,...,REJECT` 注释掉，否则会被规则先拦掉。

风险：
- `/mads/gma` 期望的是加密 protobuf，返回空 body 很可能直接解析失败 → 还是走错误回调 → 还是弹窗。
- 开着 MITM 意味着所有 HTTPS 流量都要解密，多一层开销。

如果你试了，结果无非两种：弹窗没了（那就把这个方案写回插件），或者照样弹（说明是"结果导向"，死路）。

---

## 6. 不会做的事

弹窗里提到「捐赠喵喵特权」可以去广告，说明 App 有付费去广告的权益校验。**通过抓包伪造这个权益属于绕过付费**，和"拦截广告"是两件不同性质的事，这里不做，也不建议。

如果你确实想彻底无广告无弹窗，最省事的是按开发商提示捐赠，或直接换一个同类的开源阅读器（书源是通用的，皮皮喵用的是标准书源格式）。
